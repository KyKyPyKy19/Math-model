# Отчёт о реализации блока C системы PsychMonitor

**Проект:** PsychMonitor — адаптивная система мониторинга физиологических маркеров
для психотерапевтического сопровождения
**Раздел:** программная реализация блока `C` — классификатора триггеров стрессовых эпизодов

---

## 1. Цель работы

Согласно математической модели PsychMonitor (§2.2 «Блок C: Классификатор триггеров»),
после фиксации стрессового эпизода блоком `D` клиент получает push-уведомление
и может оставить текстовый комментарий, описывающий ситуацию. Задача блока `C` —
автоматически классифицировать этот комментарий по одной из 6 предопределённых
групп триггеров.

**Задача данного этапа:** реализовать блок `C` как самостоятельный программный
модуль, обучить модель классификации на русскоязычных данных, оценить качество
по метрикам из §3.2–3.3 математической модели и обеспечить возможность
демонстрации работоспособности.

## 2. Постановка задачи классификации

**Вход:** строка `c` — свободный текст на русском языке (комментарий клиента).
**Выход:**
- `trigger_group ∈ {1,…,6}` — идентификатор класса триггера;
- `confidence ∈ [0,1]` — уверенность модели (формула 2.13);
- `user_description = c` — оригинальный текст (сохраняется в БД, §2.2.5).

**Классы триггеров (§2.2.2):**

| k | Группа              | Примеры                                   |
|---|---------------------|-------------------------------------------|
| 1 | Работа / дедлайны   | «Сложный звонок с начальником»            |
| 2 | Семья / отношения   | «Ссора с мужем из-за ребёнка»             |
| 3 | Здоровье            | «Болит голова с утра»                     |
| 4 | Друзья / общение    | «Неприятный разговор с подругой»          |
| 5 | Финансы             | «Пришли счета, задолженность растёт»      |
| 6 | Не распознано       | «Просто стало тревожно, не знаю почему»   |

## 3. Данные

### 3.1. Исходный датасет

В качестве обучающего корпуса использован **SAD v1 (Stress Annotated Dataset)** —
открытый размеченный датасет коротких англоязычных описаний стрессовых ситуаций,
собранных из Reddit и платформы краудсорсинга mTurk.

**Характеристики:**
- 6850 строк × 24 колонки;
- поле `sentence` — короткое описание (медиана 60 симв., максимум 185);
- поле `top_label` — результирующая метка по голосованию аннотаторов (9 классов);
- поле `is_stressor` — бинарный маркер реальных стрессоров.

### 3.2. Предобработка

1. **Фильтрация шума.** Отброшены 374 строки с `is_stressor == 0` (вопросы, неполные
   фразы без контекста типа «a big project»). Осталось 6476 примеров.

2. **Маппинг 9 → 6 классов.** Оригинальные категории SAD спроецированы на
   классы PsychMonitor:

   | Исходный класс SAD                                   | → | Класс PsychMonitor |
   |------------------------------------------------------|---|--------------------|
   | Work, School                                         | → | 1 (work)           |
   | Family Issues                                        | → | 2 (family)         |
   | Health, Fatigue, or Physical Pain                    | → | 3 (health)         |
   | Social Relationships                                 | → | 4 (friends)        |
   | Financial Problem                                    | → | 5 (finance)        |
   | Emotional Turmoil, Everyday Decision Making, Other   | → | 6 (unknown)        |

3. **Русификация.** Все 6476 предложений переведены с английского на русский
   через `GoogleTranslator` (библиотека `deep_translator`). Выбор обоснован:
   - короткая длина текстов (≤ 185 симв.) снижает риск искажений машинного перевода;
   - бесплатный API, достаточная пропускная способность;
   - потоковая запись с возможностью `--resume` при обрыве соединения.
   Все 6476 переводов получены без пропусков.

4. **Разделение на train/val/test.** Стратифицированный split 80/10/10 по классам
   (`sklearn.model_selection.train_test_split`, seed=42):
   - train: 5180 примеров;
   - val: 648 примеров;
   - test: 648 примеров.

5. **Class weights.** Рассчитаны обратные частоты классов для компенсации дисбаланса
   (класс 1 содержит 2080 примеров, класс 4 — всего 626). Веса нормированы к
   среднему значению 1 и применяются в функции потерь `CrossEntropyLoss`.

## 4. Архитектура модели

Реализация соответствует §2.2.3 математической модели.

### 4.1. Базовая модель

Использована **`cointegrated/rubert-tiny2`** — компактная версия RuBERT (29 млн
параметров). Выбор обоснован:
- ограничение VRAM целевой машины (NVIDIA GTX 1050 Ti, 4 ГБ);
- приемлемое качество на коротких текстах;
- быстрый инференс (~5 мс/пример) — критично для реальной системы push-уведомлений.

### 4.2. Классификационная голова

Поверх выхода `[CLS]` токена BERT-энкодера (размерность 312 для `tiny2`) добавлен
полносвязный слой с softmax-активацией на 6 классов:

```
P(y = k | c) = exp(w_k^T h + b_k) / Σ_j exp(w_j^T h + b_j)
```

что соответствует формуле 2.11 математической модели.

### 4.3. Обработка уверенности

На этапе инференса применяется правило из §2.2.3:
```
ŷ = argmax_k P(y = k | c)
conf(c) = max_k P(y = k | c)
if conf(c) < τ_conf:
    ŷ = 6   # «не распознано»
```
Порог `τ_conf = 0.4` задан в конфиге.

## 5. Обучение

### 5.1. Гиперпараметры (из §2.2.4)

| Параметр                  | Значение              |
|---------------------------|-----------------------|
| Оптимизатор               | AdamW                 |
| Learning rate             | 5 × 10⁻⁵              |
| Weight decay              | 0.01                  |
| Batch size                | 32                    |
| Max sequence length       | 128 токенов           |
| Warmup ratio              | 0.1                   |
| Эпох (max)                | 10                    |
| Early stopping patience   | 2 (по Macro-F1 на val)|
| Precision                 | FP16 (mixed)          |
| Seed                      | 42                    |

### 5.2. Технические детали

- Обучение проведено на NVIDIA GeForce GTX 1050 Ti (4 ГБ VRAM);
- Фреймворки: PyTorch 2.6.0+cu124, HuggingFace Transformers;
- Функция потерь: взвешенная CrossEntropy (§2.2.4, формула 2.14):
  ```
  L = − (1/N) Σ_i Σ_k w_k · y_ik · ln P(y = k | c_i)
  ```
- Ранняя остановка сработала на 8-й эпохе;
- Общее время обучения: ≈ 12 минут.

### 6.2. Поэлементные метрики

| Класс     | Precision | Recall | F1    | Support |
|-----------|-----------|--------|-------|---------|

**Наблюдения:**
- Классы `work` и `family` распознаются наиболее уверенно — они обладают
  специфичной лексикой (названия должностей, родственников, задач);
- Наиболее сложный класс — `friends` (F1=0.72), семантически близок к
  `family` и `unknown` (эмоциональный межличностный стресс);
- Класс `unknown` (F1=0.75) показывает приемлемое качество, несмотря на то,
  что является «собранным» из трёх разнородных категорий SAD.

### 6.3. Эффект порога уверенности τ_conf = 0.4

- Доля примеров, попавших под порог: **0.46%** (3 из 648);
- Accuracy после применения порога: 0.8194 (−0.2%);
- Macro-F1 после применения порога: 0.8086 (−0.2%);

Порог практически не влияет на основные метрики, так как модель почти всегда
даёт уверенный ответ. Его роль — **страховка от действительно неоднозначных
комментариев**, которые корректнее отнести к «не распознано», чем навязать
ложную категорию.

## 7. Программная реализация

### 7.1. Структура проекта

```
psychmonitor_classifier/
├── config.yaml                     # гиперпараметры, пути, пороги
├── requirements.txt                # зависимости Python
├── README.md                       # инструкция по запуску
├── REPORT.md                       # этот файл
├── data/
│   ├── raw/SAD_v1.csv              # исходный датасет
│   └── processed/
│       ├── sad_mapped.csv          # после фильтрации и маппинга
│       ├── sad_ru.csv              # после русификации
│       ├── train.csv, val.csv, test.csv
│       └── class_weights.json
├── src/
│   ├── config.py                   # загрузчик конфига
│   ├── label_map.py                # маппинг 9 → 6 классов
│   ├── translate.py                # EN → RU через Google Translate
│   ├── prepare_dataset.py          # split + class_weights
│   ├── train.py                    # fine-tuning RuBERT-tiny2
│   ├── evaluate.py                 # полная оценка на test
│   └── predict.py                  # демо-инференс (CLI)
├── models/rubert_trigger_classifier/   # сохранённый чекпоинт
└── reports/
    ├── train_val_metrics.json
    ├── test_metrics.json
    ├── confusion_matrix.csv
    ├── confusion_matrix.png
    └── confidence_histogram.png
```

### 7.2. Пайплайн запуска

```bash
# Подготовка окружения (один раз)
pip install -r requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cu124

# 1. Маппинг меток (секунды)
python src/label_map.py

# 2. Перевод EN → RU (~30–50 мин)
python src/translate.py

# 3. Split train/val/test
python src/prepare_dataset.py

# 4. Обучение (~12 мин на GTX 1050 Ti)
python src/train.py

# 5. Оценка на test
python src/evaluate.py

# 6. Интерактивное демо
python src/predict.py --interactive
```

### 7.3. Формат ответа `predict.py`

На каждый входной комментарий модуль возвращает JSON, соответствующий схеме
записи в БД PsychMonitor (§2.2.5):

```json
{
  "input": "Опять дедлайн горит, начальник требует отчёт к утру",
  "predicted_class_id": 1,
  "predicted_class_name_ru": "Работа / дедлайны",
  "confidence": 0.9412,
  "trigger_group": 1,
  "user_description": "Опять дедлайн горит, начальник требует отчёт к утру",
  "probabilities": {
    "Работа / дедлайны":       0.9412,
    "Семья / отношения":       0.0138,
    "Здоровье / самочувствие": 0.0092,
    "Друзья / общение":        0.0211,
    "Финансы":                 0.0074,
    "Не распознано":           0.0073
  },
  "reason": "argmax"
}
```

Оригинальный текст `user_description` **сохраняется независимо** от результата
классификации — требование §2.2.5 соблюдено.

## 9. Выводы

1. **Блок `C` реализован как самостоятельный программный модуль**, пригодный
   для демонстрации работоспособности независимо от остальных компонентов
   системы PsychMonitor.

2. **Все целевые показатели качества из математической модели достигнуты
   с запасом:** Macro-F1 = 0.81 (цель 0.70), AUC-ROC = 0.96 (цель 0.85).

3. **Модель хорошо калибрована** (ECE ≈ 5.8%), что делает осмысленным
   использование значения `confidence` как фактора доверия к предсказанию
   на стороне терапевта.

4. **Механизм порога уверенности `τ_conf = 0.4`** работает как предусмотрено:
   перехватывает редкие неоднозначные случаи (< 0.5% на test), не ухудшая
   основные метрики.

5. **Оригинальный текст комментария сохраняется** в `user_description`
   независимо от результата классификации, что соответствует требованию
   §2.2.5 и обеспечивает терапевту доступ к первичным данным клиента.

6. **Потенциальные направления улучшения** (при наличии ресурсов):
   - замена базовой модели на полный `DeepPavlov/rubert-base-cased`
     (оценочный прирост +2–4% F1);
   - аугментация данных backtranslation'ом для редкого класса `friends`;
   - дополнительная ручная разметка 100–200 комментариев класса `unknown`
     для уточнения границ между категориями.

---

**Итог:** программная реализация блока `C` подтверждает корректность и
практическую применимость предложенной математической модели классификации
триггеров стрессовых эпизодов для системы психотерапевтического
сопровождения PsychMonitor.
